- (decision) Paradigm: pipes and filters over a file blackboard; inside the jar, ports and adapters. Binds all FRs. Prevents stages calling each other directly or sharing memory, so any stage can be rerun alone and a skill can be swapped without touching the jar
- (decision) AD-1 deterministic/judgement boundary is the file system: the jar never calls AI, skills never write into the knowledge base or a slice. Prevents a skill 'fixing' extracted data and the fix being lost on re-extract
- (decision) AD-2 one writer per file in the work folder. Prevents two stages overwriting each other (e.g. skill and operator both editing matches.csv status)
- (decision) AD-3 the jar never guesses and unread content is found by observation: readers go through a wrapper that records what was read; the not-read list is source minus read. Prevents a hand-kept list drifting from the code (the first attempt lost three privilege grants this way)
- (decision) AD-4 row identifier = estate::layer::qualified name, layers phys/bmm/pres/cat; built from names never from GUIDs; a duplicate is an error row. Prevents skills and jar citing rows differently
- (decision) AD-5 text is verbatim and every representation the source holds gets its own column. Prevents a builder keeping only the rendered formula
- (decision) AD-6 formats live only in inbound adapters (mds, catalog, docx); core has no XML or zip types. Prevents format details leaking into slice and check logic
- (decision) AD-7 repository and catalog are paired only by being in one estate folder; the report-to-repository link lives in its own table report_lineage.csv and lineage.csv is never widened. Prevents an unverified cross-store link sitting in the same table as verified repository lineage
- (decision) AD-8 CSV contract: UTF-8, RFC 4180 quoting, LF, header row, fixed column order, rows sorted by row identifier, manifest.csv lists every table; no spreadsheet guard columns. Prevents two writers emitting incompatible CSV and makes reruns byte-identical
- (decision) AD-9 a slice has exactly the knowledge base schema (same file names and columns, fewer rows). Prevents skills needing two readers
- (decision) AD-10 FSD anchors: the jar numbers every paragraph and table cell in fsd.md; fsd_items.csv and matches.csv cite anchors. Prevents the trace skill and the check disagreeing on what an FSD item is
- (decision) AD-11 matches.csv is the contract between trace skill, check, operator and slice: fixed columns and four status values; the skill writes proposed/unmatched only, the operator alone writes confirmed/rejected, in a separate decisions column. Prevents a skill confirming its own proposal
- (decision) AD-12 citation syntax [kb:<row id>] in every skill-written document. Prevents each skill inventing its own citation form, and lets a later jar command verify citations
- (decision) AD-13 skills need only read file, write file, run a local command; authored once under skills/ and copied identically to .agents/skills/ and .claude/skills/; a test checks the copies match. Reality: this repo's BMad install already uses .agents/skills with .github/agents/*.agent.md for Copilot and .claude/skills for Claude
- (decision) AD-14 one jar, four subcommands (extract, slice, fsd-text, check-matches), shared exit codes 0/2/3; each command rewrites only its own output folder and refuses to clean a folder it did not write. Prevents per-command conventions diverging
- (decision) AD-15 no build tool and no test library: build.sh/build.cmd call javac --release 11 and jar; tests are plain Java classes run by a small in-repo runner. Prevents a builder adding Maven/JUnit that the target system cannot fetch
