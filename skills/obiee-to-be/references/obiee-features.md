# OBIEE features that need a decision in Power BI

Each row below is something OBIEE does that Power BI does not do the same way by itself. When a packet shows one, you do not translate it: you state what OBIEE holds (with its marker, logic quoted exactly), list the options, say which is like for like, and ask. The decision goes to the notes as a `- Decision:` line, to `Decisions needed`, and to an open question with an `Options:` line. A measure that depends on an undecided feature gets no proposed definition.

The options are starting points. Leave one out if the packet shows it cannot apply, and add one if the packet suggests it. Do not choose.

| Feature | How you recognise it in a packet | Why it needs a decision | Options to offer | What the question must bring back |
|---|---|---|---|---|
| Time-series function | A formula with AGO, TODATE or PERIODROLLING | Power BI needs a date table marked as such, and a pattern chosen per function; the period OBIEE shifts by comes from a level of the time drill path | (a) time-intelligence over a date table at day level; (b) the shifted values prepared in the new tables; (c) the figure is dropped from the tab | Which option; which date field of the fact drives it; whether the new time table holds every day |
| Several sources at different levels of detail | A business table with more than one source, each with its own level of detail and priority group | OBIEE picks a source per query; Power BI reads the tables it is given. The same measure may be mapped differently per source | (a) keep only the detail table and let the model add up; (b) keep the summary tables as aggregations of the detail table; (c) keep all and choose per visual | Which tables are kept; whether detail and summary tables agree, with a query that compares their totals; who loads the summaries |
| A measure mapped differently in two sources | The same field "here is" one expression in one source and another in a second (a multiplication in one only) | The number depends on the source OBIEE picks, so there is no single definition to carry over | (a) the detail mapping is the definition; (b) the summary mapping is; (c) both exist as separate measures | Which mapping is meant, and the comparison of both totals |
| A switch on a value set per user | A formula with INDEXCOL, or CASE on VALUEOF(NQ_SESSION. …) | The model has no session variables; what a user sees would depend on a value OBIEE sets at login | (a) a slicer the user sets; (b) a per-user setting held in a table and applied by a security role; (c) one fixed choice for everyone | Which option; where the per-user value comes from today; the values it can take |
| A fixed number in a formula | A mapping or formula with a literal factor (a multiplication by 0.76) | A like-for-like design would hard-code it again; whether it is still right is not recorded | (a) keep the fixed number; (b) read it from a table | The source of the number and whether it changes |
| Lookup or translation | A formula with LOOKUP, or a field mapped from a translation table by a language value | The text shown depends on the user's language | (a) one language only; (b) a translation table related to the dimension, chosen by a slicer or by the user's language | Which languages are needed; the table and column that hold them |
| Displayed name set by a variable | A table or field whose display name is a formula with VALUEOF | Names in a model are fixed text, or translated through its own mechanism | (a) fixed names; (b) the model's translations | The names users see today, per language |
| Parent-child drill path | A drill path the packet calls parent-child, with a relationship table | Power BI has no parent-child hierarchy type; depth is not fixed | (a) flatten to a fixed number of level columns; (b) keep parent and child fields and compute the path in the model | The greatest depth in the data; whether the relationship table is kept as a new table |
| Row filter | A security row with a filter on a source | It must become a role in the model, and the roles and their members are not all in the export | (a) one model role per OBIEE role with the same condition; (b) a table of who may see what, filtered by the user's identity | The roles and their members; whether the condition reads a per-user value |
| Permissions on fields or tables | Object permissions in the security packet | The model can hide objects per role, but only where roles are defined | (a) the same restrictions as model roles; (b) no restriction below the report | Who holds each role today |
| Writeable measure | A measure with writeable true | A model measure cannot be typed into | (a) read-only, loaded by a process; (b) a separate entry form writes to the new table; (c) write-back is no longer needed | Whether the tab takes entries, and what loads the table |
| Implicit fact column | The overview says which measure OBIEE uses when a query names none | Power BI has no such default; relationships decide which rows a dimension shows | (a) nothing to build; (b) a visual-level filter that reproduces it where a list of dimension values must be limited | Whether any visual of the tab shows a dimension with no measure |
| Content filter on a source | A source with a content filter (where) | The filter decides which rows a table contributes; it must be applied somewhere | (a) in the new view; (b) in the load of the new table; (c) in the model | Where the filter is to live; whether the excluded rows are needed elsewhere |
| A join inside a source | A source that reads two or more database tables, with a join type and cardinality | The model table has to come from one object, or from related tables; an outer join changes which rows count | (a) a new view that joins them the same way; (b) separate new tables related in the model | Which shape; for an outer join, whether unmatched rows must stay |
| Join that is not a plain one-to-many inner join | A cardinality printed as anything else, a join type other than Inner, a complex join with a condition | A model relationship is one-to-many or many-to-many with a filter direction; a condition such as 1=1 has no relationship form | (a) a relationship with the nearest cardinality; (b) no relationship, and the combination done in a view or a measure | What the join is for; for a condition, what it is meant to pair |
| A table that is a query | A database table of type select, with its SQL | It has to exist somewhere | (a) a view with the same SQL; (b) a calculated table in the model | Where it lives; whether its SQL is specific to the old database |
| A call to a database function | EVALUATE or a database-specific function in a formula or query | It runs in the old database and may not exist in the new one | (a) the same function on the new platform; (b) rewritten in the model; (c) prepared in the new table | What the function returns, with its definition from the database |
